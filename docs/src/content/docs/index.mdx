<section class="landing-section not-content">
  <div class="landing-section__header">
    <h2>Selected direction</h2>
    <p>
      The active construction is active-static secure-with-abort collective BGV
      setup, direct encrypted ballots, ballot validity proofs for the fixed
      encrypted-ballot relation, public ciphertext aggregation, bounded-domain mobile
      evaluator replay, unanimous target finality, and one-shot target-bound
      decryption of <code>C_target</code> only.
    </p>
  </div>

  <div class="landing-split-grid">
    <Card title="Direct encrypted ballot path">
      <div class="landing-card-copy">
        <p>
          Each voter publishes one encrypted ballot. Verification must check
          active-static setup evidence, the ballot proof, the first valid ballot
          per voter, and the encrypted ballot aggregate from public ciphertexts.
        </p>
        <p>
          The evaluator is checked by deterministic bounded-domain mobile replay.
          <code>C_topK</code> is encrypted, but it is not an authorized
          decryption target. Only the finalized and replay-matched
          <code>C_target</code> can be decrypted.
        </p>
      </div>
    </Card>

    <Card title="Current limits">
      <div class="landing-card-copy">
        <p>
          The setup, direct proof, aggregation, and browser evidence are internal
          development evidence. They are not supported-phone evidence, production
          readiness, or a complete public voting API.
        </p>
        <p>
          Active-static setup, VSS, final claim-bearing ballot package evidence,
          bounded-domain evaluator replay, mobile evidence, and target-bound
          decryption remain open.
        </p>
      </div>
    </Card>

  </div>
</section>

      3. **Verify current public evidence.**
         Use the current helpers for development verification and package integration.
      4. **Keep the current limits explicit.**
