<section class="landing-section not-content">
  <div class="landing-section__header">
    <h2>Selected direction</h2>
    <p>
      The active construction is direct BGV-encrypted ballots, public ciphertext
      aggregation, deterministic mobile evaluator replay, target finality, and
      target-bound threshold decryption.
    </p>
  </div>

  <div class="landing-split-grid">
    <Card title="Direct encrypted ballot path">
      <div class="landing-card-copy">
        <p>
          Each voter publishes one encrypted ballot. Verification must
          check the ballot proof, select the first valid ballot per voter, and
          recompute the encrypted ballot aggregate from public ciphertexts.
        </p>
        <p>
          The evaluator is checked by deterministic mobile replay. Only the
          finalized and replay-matched <code>C_target</code> can be decrypted.
        </p>
      </div>
    </Card>

    <Card title="Current limits">
      <div class="landing-card-copy">
        <p>
          The direct proof, aggregation, and browser evidence are internal
          development evidence. They are not supported-phone evidence, production
          readiness, or a complete public voting API.
        </p>
        <p>
          Ballot proof soundness, zero-knowledge accounting, public proof
          transport, sparse target projection, mobile replay, and target-bound
          decryption remain open.
        </p>
      </div>
    </Card>
  </div>
</section>

<section class="landing-section not-content">

    </p>

  <div class="landing-steps-shell">

      2. **Import from the root.**
         Use `sealed-lattice` for the supported public API.
      3. **Verify current public evidence.**
         Use the current helpers for development verification and package integration.
      4. **Keep the current limits explicit.**
         Ballot generation, casting, aggregation, evaluator replay, target-bound decryption, and result release are not complete public APIs yet.
    </Steps>
