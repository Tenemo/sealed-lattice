# Security policy

`sealed-lattice` is development software. It has not been independently audited, certified, or approved for production elections. Do not use it for real ballots, real ballot secrecy, or production result authorization.

## Report a vulnerability

Use GitHub private vulnerability reporting when available. If it is unavailable, open a minimal public issue requesting a private contact path without including exploit details.

Include the affected package version or commit, a minimal reproduction, the expected property, the observed behavior, and whether secret material or private data may have been exposed. Do not attach real election data, private keys, ballots, shares, witnesses, or unpublished exploit material.

## Supported versions

No release is supported for production election use. Security fixes target the active repository and current published package line unless a later release policy states otherwise.

The local copy-on-write transaction store has no authenticated append-only journal or externally anchored current-head identity. Its recovery cleanup can make a lost or corrupt committed index appear absent, and a complete namespace rollback can present an older internally authentic snapshot. Web Locks do not provide rollback freshness. As summarized in the [durable state recovery assessment](reference-documents/durable-state-recovery-assessment.md), certified durable authority requires an explicit replicated or monotonic freshness source under a stated fault model. If the freshest state cannot be authenticated, retire the affected witness identity and secret material; do not recreate its missing reservation, counter, vote, or release record.

### SEC-016: theorem-matched threshold smudging

Target partial decryption does not yet implement theorem-matched threshold smudging. The current zero-share coefficients are deterministically derived from public target and profile bindings under a fixed coefficient bound of 16. The accepted target-share profile does not bind mandatory smudging scale and tail-cut parameters `(s, tau)`, fresh private sampling, or a complete derivation showing that the exact BGV/RNS moduli, interpolation points, evaluator-noise bound, corruption threshold, and statistical failure target satisfy decryption invertibility, decryption correctness, simulation invertibility, and simulation flooding Conditions (C1)-(C4). The current partial-decryption path therefore has no established IND-CPA-D, IND-CPAD, or threshold simulation-security claim.

Closure requires a selected theorem and construction, profile-bound `(s, tau)` and derived bounds, mandatory fresh private smudging for every partial decryption, correctness and failure-probability accounting, and a proof that the resulting deployed parameters satisfy the theorem's complete hypotheses. Do not publish or use target partial-decryption shares with real secret material, and do not claim that current smudging hides the secret share or evaluation noise. Treat target decryption as development-only until the profile-bound construction and its full security argument are implemented and reviewed.

## Correct use

- Import only from the published `sealed-lattice` package root. Private workspace packages, fixtures, and test helpers are unsupported.
- Supply `verifySetupPackage` with manifest and roster hashes derived from an externally accepted context, never from the untrusted package being verified.
- Require positive verification of canonical encodings, hashes, roots, signatures, proof families, contexts, and prerequisites. Do not ignore structured refusals or replace them with producer-supplied labels.
- Do not decrypt individual ballots, aggregate scores, ranks, comparisons, evaluator intermediates, or arbitrary ciphertexts.
- Do not expose VSS shares, trustee secret shares, encryption randomness, proof witnesses, proof randomness, decryption witnesses, or local secret state.
- Do not retry a failed multiparty operation under the same relevant secret material.
- Do not treat IndexedDB atomicity, Web Lock ownership, authenticated local records, or checkpoint manifests as rollback-resistant freshness or durable one-shot authority.
- Do not treat fixtures or native, Node.js, desktop-browser, or emulated runs as production or supported-phone evidence.
- Protect any caller-managed secret-storage key with uniformly random platform-protected key material; do not derive it from a password or another low-entropy secret.

Endpoint compromise, malicious same-origin code, compromised platform key storage, denial of service, and side channels without explicit evidence are outside the package's current security boundary.
