# WASM package

This package owns Rust/WASM loading, typed wrappers, and runtime-specific instantiation details.

The current release ships the transcript-core command contract around the Rust crate. It verifies canonical objects, fixture replays, chunk roots, reserved protocol hash derivation, `GF(65537)` interpolation/comparison checks, development passive BGV setup package verification, and the accepted collective BGV setup verifier gate. The setup path includes carry-aware VSS relation profile binding, accepted BDLOP/LNP setup commitment parameter accounting, setup-proof profile and challenge-domain binding, full LaZer-style LNP tbox proof-byte generation and verification for private VSS, same-secret, public-key share, relinearization, and Galois setup proof families, accepted setup-proof theorem accounting, full-profile public VSS material size accounting, root-bound setup transport certificate and chunk-manifest verification, accepted HE security certificate verification for the current direct evaluator replay boundary, transported binary public VSS material derivation for threshold-share commitments, ML-DSA-65 phase signed-root verification, common-randomness commit/reveal binding, accepted public-derivation binding, deterministic setup public-matrix coefficient sample binding, root-bound VSS coefficient commitment verification, private VSS envelope commitment-set verification, signed VSS share acceptance and complaint-abort verification, proof-bearing same-secret and public-key share verification, proof-bearing relinearization and Galois key-share verification, accepted public evaluation-key assembly, roots-only local trustee setup state commitment verification without aggregate-opening roots, neutral accepted-setup command error mapping, the internal direct encrypted ballot command, stable canonical rejection codes, and explicit WASM kernel integrity expectations in Node and browser/WASM builds.

The WASM package is not a public voting API. Raw BGV operations, proof witnesses, encryption randomness, plaintext oracle helpers, evaluator intermediate openings, raw VSS shares, setup secrets, and decryption helpers remain internal. The passive setup command is development evidence only and cannot close `CollectiveBgvSetup-v1`.
